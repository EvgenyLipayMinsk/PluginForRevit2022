# Разработка AerBIM

При любой задаче, которая меняет исходники, интерфейс или поведение плагина, автоматически запускай настроенных субагентов AerBIM на соответствующих этапах. Веди диалог с пользователем в основном чате и передавай агентам согласованные решения и критерии приёмки.

1. Запусти `aerbim-development-coordinator` при постановке задачи. С ним уточни поведение и критерии приёмки. Когда потребуется решение пользователя, задай вопрос в основном чате.
2. Передай согласованную задачу `aerbim-csharp-developer`. Передай итоговый checkout и перечень изменений `aerbim-build-engineer` для тестовой сборки под целевую версию Revit. MSI собирай по отдельной команде.
3. Передай точную сборку и сценарии `aerbim-integration-tester`. Возвращай подтверждённые дефекты разработчику, затем повторяй сборку и затронутые проверки. Если Revit или тестовая модель недоступны, зафиксируй блокер и результаты доступных проверок.
4. Подключай `aerbim-instructions-writer` после стабилизации поведения. Поручи ему определить, влияет ли изменение на инструкции. Для затронутых сценариев он готовит краткие версии для пользователя Revit и для ИИ через MCP. Если изменение внутреннее, достаточно вывода о применимости документации.
5. После успешных интеграционных проверок передай пользователю сценарий ручной приёмки и дождись результата. Найденные дефекты верни в цикл исправления. После подтверждения проведи предкоммитное ревью с `aerbim-plugin-reviewer` и сделай коммит, если он входит в поручение.

Основной чат запускает следующие роли сам, если координатору недоступна вложенная делегация. Если именованный профиль недоступен, прочитай его TOML в `.codex/agents/`, передай его инструкции доступному субагенту и сообщи об этом. Для вопросов и исследований без изменений подключай только роли, относящиеся к запросу.

Формат передачи задач, сборок и результатов проверок описан в [WORKFLOW.md](WORKFLOW.md). Общие навыки AerBIM хранятся в `.agents/skills/`.
